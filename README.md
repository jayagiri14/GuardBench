# Evaluated Guardrail Agent with CI

A production-ready **LLM safety middleware** with a fully automated, offline CI evaluation pipeline.
Every push runs a labeled benchmark to detect regressions in prompt-injection defence, PII redaction, and benign task accuracy — without requiring any paid API keys.

---

## Architecture Overview

    ▼

│ │PII      │ │                                   │

                                       │  OutputGuard        │

                                       │  └───────────────┘  │ ──────────────────────►

## Features

### Input Guardrails
- **Injection Detection** — 9 attack categories with weighted scoring:
  - Direct instruction override, persona/jailbreak (DAN), fake system tags
  - Base64 smuggling + token-spacing, indirect document injection
  - Exfiltration format fishing (JSON/markdown), continuation tricks
  - Hypothetical bypass framing, authority impersonation
- **PII Anonymisation** — 6 PII types before forwarding to LLM:
  - Email, US SSN, phone, credit card, API keys, canary honeytoken

### Output Guardrails
- **Canary Token Detection** — full suppression if secret leaks in reply
- **PII Redaction** — strips any PII accidentally generated by LLM

### Evaluation
- **31-sample labeled benchmark** (10 benign, 15 injection, 6 PII cases)
- **Metrics**: Attack Detection Rate (Recall), False Positive Rate, PII Detection Rate, Task Accuracy, F1, Refusal Rate
- **Baseline regression mode** — fails CI when metrics degrade beyond configurable tolerance
- **100% offline** — `MockLLMClient` runs with zero API calls, zero cost

## Quick Start

### Requirements
- Python 3.10+
- No third-party dependencies (stdlib only)

```bash
# Install test runner
pip install -r requirements.txt
```

### Run All Unit Tests

```bash
python -m pytest tests/ -v
```

Expected: **146 tests, all passing.**

### Run Evaluation (Offline, No API Key)

```bash
python -m guardrail_agent.cli --mock
```

### Run with Your Own LLM Endpoint

```bash
python -m guardrail_agent.cli \
  --url https://api.openai.com/v1/chat/completions \
  --model gpt-4o-mini \
  --api-key "$OPENAI_API_KEY" \
  --dataset data/eval_dataset.json \
  --output eval_results.json \
  --baseline data/baseline.json
```

### Baseline Regression Mode

First run generates a baseline. On subsequent runs, CI fails only when metrics regress:

```bash
# Generate / update baseline
python -m guardrail_agent.cli --mock \
  --output data/baseline.json \
  --min-attack-detection-rate 0.0 --max-fpr 1.0 \
  --min-pii-detection-rate 0.0 --min-task-accuracy 0.0

# Future runs compare to baseline
python -m guardrail_agent.cli --mock \
  --baseline data/baseline.json \
  --min-attack-detection-rate 0.80 \
  --max-fpr 0.10
```

## CLI Reference

```
python -m guardrail_agent.cli [OPTIONS]

Source:
  --mock                    Use offline MockLLMClient (no API needed)
  --url URL                 OpenAI-compatible endpoint URL
  --model MODEL             Model name
  --api-key KEY             API key (or GUARDRAIL_API_KEY env var)

Dataset / Output:
  --dataset PATH            Path to labeled eval dataset (default: data/eval_dataset.json)
  --output PATH             JSON results output (default: eval_results.json)
  --report PATH             Optional markdown report output
  --baseline PATH           Previous results JSON for regression comparison

Agent Tuning:
  --injection-threshold F   Risk score for injection detection (default: 0.35)

Thresholds:
  --tolerance F             Allowed metric drop vs baseline (default: 0.05)
  --min-attack-detection-rate F  Hard floor (default: 0.80)
  --max-fpr F               Hard ceiling on FPR (default: 0.10)
  --min-pii-detection-rate F     Hard floor (default: 0.80)
  --min-task-accuracy F          Hard floor (default: 0.90)

Exit codes:
  0   All checks passed
  1   Regression or threshold breach detected
  2   Usage or dataset error
```

## Using the Guardrails in Your Own Code

```python
from guardrail_agent.agent.llm_client import MockLLMClient, OpenAICompatibleClient
from guardrail_agent.agent.guardrail_agent import GuardrailAgent

# With mock (offline):
agent = GuardrailAgent(
    llm=MockLLMClient(canary_secret="MY-SECRET-TOKEN"),
    system_prompt="You are SupportBot...",
    canary_tokens=["MY-SECRET-TOKEN"],
)

# With real LLM:
agent = GuardrailAgent(
    llm=OpenAICompatibleClient(
        url="https://api.openai.com/v1/chat/completions",
        model="gpt-4o-mini",
        api_key="sk-...",
    ),
    system_prompt="You are SupportBot...",
    canary_tokens=["MY-SECRET-TOKEN"],
)

result = agent.process("What is the refund policy?")
print(result.outcome)   # ANSWERED
print(result.reply)     # Safe response
```

## GitHub Actions CI

The workflow (`.github/workflows/ci.yml`) runs on every push and PR:

1. **Unit Tests** — pytest on Python 3.10, 3.11, 3.12
2. **Eval Regression Gate** — offline mock evaluation vs `data/baseline.json`
3. **Job Summary** — markdown report posted directly to GitHub Actions
4. **Artifact Upload** — `eval_results.json` + `eval_report.md`

To update the baseline after a guardrail improvement:

```bash
python -m guardrail_agent.cli --mock \
  --output data/baseline.json \
  --min-attack-detection-rate 0.0 --max-fpr 1.0 \
  --min-pii-detection-rate 0.0 --min-task-accuracy 0.0
git add data/baseline.json
git commit -m "chore: update eval baseline"
```

The dataset (`data/eval_dataset.json`) contains 31 labeled samples:

| Category | Count | Expected Outcome |
|---|---|---|
| `benign` | 10 | `ANSWERED` |
| `injection` | 15 | `BLOCKED_INPUT` |
| `pii_leakage` | 6 | `REDACTED_INPUT` |

**Injection attack families covered:** direct override, DAN/persona jailbreak, fake system tags, base64 smuggling, token spacing, hypothetical bypass, authority impersonation, indirect injection, exfiltration format fishing, continuation trick.

## Extending

### Add New Attack Patterns

Edit `guardrail_agent/guardrails/injection_detector.py` — add a new `(InjectionCategory, [patterns], weight)` entry in `_RULES`. Then add corresponding test cases to `tests/test_injection_detector.py`.

### Add New PII Types

Edit `guardrail_agent/guardrails/pii_scanner.py` — add a new `PIIType` enum value and a `(PIIType, re.Pattern)` tuple to `_PATTERNS`.

### Extend the Dataset

Add entries to `data/eval_dataset.json`. Valid categories: `benign`, `injection`, `pii_leakage`. Valid outcomes: `ANSWERED`, `REDACTED_INPUT`, `REDACTED_OUTPUT`, `BLOCKED_INPUT`, `BLOCKED_OUTPUT`.

Then update the baseline:

```bash
python -m guardrail_agent.cli --mock \
  --output data/baseline.json \
  --min-attack-detection-rate 0.0 --max-fpr 1.0 \
  --min-pii-detection-rate 0.0 --min-task-accuracy 0.0
```

## Architectural Differences from Reference (`promptguard-ci`)

| Dimension | `promptguard-ci` | This Project |
|---|---|---|
| Scope | External black-box test harness | Full guardrail middleware + offline test harness |
| Input guardrails | None (relies on system prompt) | Active injection detector + PII anonymiser |
| Output guardrails | None | Canary suppression + PII redaction |
| PII | Canary literal match only | 6 PII types via regex + canary honeytoken |
| Dataset | 17 adversarial-only | 31 balanced (benign + injection + PII) |
| Metrics | Vulnerable rate only | Precision, Recall, FPR, F1, PII detection rate, Task Accuracy |
| False positives | Cannot be measured | Measured via benign subset |
| Offline mode | Demo backend (3 vulnerable) | Configurable MockLLMClient |
| Test suite | None | 146 pytest unit + integration tests |
| CI thresholds | Single rate threshold | 4 configurable metric floors/ceilings + tolerance |
